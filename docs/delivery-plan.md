# GuideKit delivery plan

Owner-approved scope: complete the visual/voice company-agent platform with dependable workflows, company knowledge, real host integration and operational foundations. Visual redesign is deferred. The local ChatGPT-subscription demo remains the default. A separately configured hosted inference adapter may be prepared, but no paid calls or public deployment are enabled without configuration and authorization. Native desktop capture and arbitrary cross-origin/canvas control are separate capabilities, not implied by the website SDK.

Baseline: `73f58d3`, 111 unit/integration tests and 28 Chromium tests, live Codex and TigerGraph proof. Work continues on `feat/platform-completion`, based on the unmerged guidance branch. No merge to main is authorized by this plan. Existing customer/demo data must survive every schema upgrade and restart.

## Component contracts and invariants

- Model output remains strict data: current known target IDs, bounded annotations, optional journey continuation state. No executable code or arbitrary selectors. Conversation goals are untrusted; completed evidence contains labels/roles/IDs, never field values.
- Each adaptive task owns a generation/revision, one in-flight inference, a six-continuation budget by default (host-configurable from 1 through 24), and debounced semantic changes. Scroll, pointer motion and keystrokes alone must not cause inference calls. Direct assistant-executed host mutations require independent authorization and explicit visitor approval; manual native controls retain their normal application permissions.
- A host can report a bounded pending operation and later a verified `step` or `goal` result. A native final submit preserves legacy terminal behavior unless explicitly scoped as an intermediate step. Pending saves, file pickers and jobs do not imply completion. A result arriving while chat is open waits for explicit Resume; stale, cancelled or expired tasks cannot regain ownership.
- Published snapshots are immutable. Retry targets the same snapshot; newer ready versions cannot be overwritten by a late older sync. Previously pinned sessions continue against their original snapshot. Unpublishing prevents new sessions; it does not silently revoke existing issued credentials.
- Graph credentials stay server-side. A configured graph outage is explicit. A failed candidate never receives a new visitor session. Legacy snapshots are preserved by migration and can be rechecked/retried.
- Dashboard changes preserve unsaved config/document edits. The shared SDK remains framework independent and reusable by different companies.
- Cutroom is one host adapter. Its existing revision, idempotency, validation, media privacy and undo boundaries remain authoritative. Integration must not read/upload private media merely to supply context.

## Execution and evidence

Work is split across isolated SDK, dashboard and operations branches, with root owning contracts, server, database, integration and shared documentation. Each change receives meaningful focused tests, then the applicable combined checks. Commit coherent checkpoints, scan tracked source before each push, and keep PRs reviewable. Update `docs/status.md` with implemented, fixture-tested, live-tested, deployed and blocked distinctions. No quality percentage or production-ready claim substitutes for the acceptance evidence.

Outstanding external decisions are requested while independent implementation continues. Paid accounts, credentials, public exposure, external delivery and physical-device acceptance are not simulated as completed. Every remaining gate stays in this ledger until its evidence is recorded.

## Current release boundary

The 2026-10-30 workflow follow-up adds reusable SDK0.3 progress semantics and a broader public Cutroom adapter, rather than a fixed two-clip script. Its actual TigerGraph publication contains ten factual sources. A live subscription request crossed title creation and canvas settings and was independently read back. Automated guidance actors use explicit model fixtures and verify real local Cutroom saves, media jobs and export output; those checks do not claim universal model accuracy.

The local platform, source-level Cutroom integration and commercial adapter preparation are implemented. The developer dashboard and local demos stay on loopback. Cutroom changes remain committed on its own `feat/guidekit-integration` branch, without merging or publishing that separate repository. GuideKit changes are reviewed in the stacked platform PR.

Human testing confirmed transcription works. On 2026-10-29 the user reported browser narration still sounded robotic after trying alternatives and explicitly deferred that quality work. The picker, preview and speed preference remain available; no paid TTS provider was introduced.

Remaining deployment/device gates are public HTTPS hosting/domain/secrets, live API-provider inference if selected later, real external account delivery, npm/CDN publication if wanted, packaged Electron/physical mobile and physical input methods. A real elapsed 600-second Chromium lifecycle check passed with explicit model/speech fixtures and zero tracked resources after destroy; this does not claim an all-day live-provider or physical-device stress test. Docker configuration validates, but its image/login were not run because the daemon was unavailable. SSO, billing, broader ingestion and visual redesign remain separately scoped product phases. A documented local export/erasure procedure does not claim one-click external graph deletion.
